# AntiSmurf 规则设置与 UI 校准手册

本文档面向 **内存模式6** 安装包用户，说明如何配置评分规则、踢人阈值，以及如何校准踢人坐标。

---

## 一、主界面入口

| 按钮 | 位置 | 作用 |
|------|------|------|
| **评分规则** | 窗口右上角 | 打开规则编辑器，增删改评分表达式 |
| **UI 校准** | 窗口右上角 | 校准 10 个槽位右键坐标与踢人菜单偏移 |
| **数据源** | 窗口右上角 | 可选：指定录像上传目录、导入外部规则包 |
| **设置** | 窗口右上角 | 社区 API、踢人冷却、分数/嫌疑字体颜色等 |
| **刷新** | 窗口右上角 | 手动立即扫描房间玩家并确认；1.5 秒内连续点击会重新确认 SC2 进程与句柄位置 |
| **批量白名单** | 窗口右上角 | 一次粘贴多个句柄加入白名单（自动识别分隔符、补全 `5-S2-1-` 前缀） |
| **白名单模式** | 窗口右上角勾选 | 自动踢出白名单以外的所有玩家（仅白名单玩家可留房） |
| **Dry Run** | 窗口右上角勾选 | 开启时只模拟踢人，不实际点击 |
| **极高嫌疑自动踢** | 灰度版可能隐藏 | 分数达阈值时自动踢人（需关闭 Dry Run） |
| **拉黑+200** | 玩家行 | 一键拉黑（加入黑名单并 +200 嫌疑分），玩家名称以嫌疑色标出 |

> **说明**：主界面状态栏会显示「句柄位置=已确认/未确认」与「玩家句柄=已抓到」；游戏版本更新导致句柄位置失效时程序会自动嗅探更新并持久化。

## 二、评分规则编辑器

### 打开方式

主界面 → **评分规则**

### 基本操作

1. **预设**：下拉选择 `balanced` 等预设，可一键恢复默认规则。
2. **添加规则**：新建一条表达式规则。
3. **删除规则**：删除当前选中的规则。
4. **保存**：写入 `config/user.toml`，立即生效。
5. **导入 / 导出**：分享 `.toml` / `.txt` 规则包。
6. **AI 助手**：填写 API Key（OpenAI 兼容，默认 DeepSeek），用自然语言描述需求，AI 生成规则后预览确认追加。
7. **IDE 编辑 / 从文件重载**：将规则导出为 `config/rule_edit.toml` 并用 VSCode 打开编辑，保存后「从文件重载」应用。

### 单条规则结构

每条规则由三部分组成：

```
[ 值 A ]  (可选: ±×÷ [ 值 B ])  [ 比较符 ]  [ 比较值 ]  →  权重(真) 分
```

- **条件为真**：加上「权重(真)」对应的分数。
- **条件为假**：若设置了「权重(假)」，则加上该分（通常为 0）。
- **最低对局数**：部分规则可设 `min_games`，要求 playlike 对局数达到后才生效。

### 默认 balanced 预设（参考）

| 表达式 | 得分 |
|--------|------|
| `MMRplaylike.max − MMR.min ≥ 800` | 80 |
| `句柄末段 profile ID ≥ 1250000` | 20 |

当玩家 **总分 ≥ kick_threshold**（默认 100，可在 `user.toml` 的 `[scoring]` 修改）且开启自动踢人、关闭 Dry Run 时，会触发踢人。

## 三、可用变量一览

在规则编辑器中从下拉菜单插入变量；角色相关需手动输入，如 `role.mmr.Energizer`。

### 玩家信息

| 变量 | 含义 |
|------|------|
| `handle.profile_id` | 句柄末段数字（如 `5-S2-1-12345678` 取 `12345678`） |
| `player.has_team` | 是否有战队名（0 或 1） |

### 核心 MMR / MMRplaylike

| 变量 | 含义 |
|------|------|
| `mmr.survivor` / `mmr.kerrigan` | 各阵营核心 MMR |
| `mmr.min` / `mmr.max` | 核心 MMR 最小 / 最大 |
| `mmr_playlike.survivor` / `mmr_playlike.kerrigan` | 反推核心 MMRplaylike |
| `mmr_playlike.min` / `mmr_playlike.max` | MMRplaylike 最小 / 最大 |
| `playlike.avg_all` | 全局 playlike 均值 |

### 按角色（手动输入角色名）

| 变量格式 | 含义 |
|----------|------|
| `role.mmr.{角色名}` | 该角色官方 MMR |
| `role.playlike.{角色名}` | 该角色近期 playlike 均值 |
| `role.class_mmr.{角色名}` | 该角色 class MMR 偏移 |

### 社区数据与嫌疑指标

| 变量 | 含义 |
|------|------|
| `data.has_mmr` | 是否有社区 MMR（0/1） |
| `data.has_playlike` | 是否有 playlike 对局（0/1） |
| `data.playlike_game_count` | playlike 对局条数 |
| `data.community_match_count` | **社区各角色 `plays` 之和**（对局总数） |
| `lift.core_max` | playlike 高于核心 MMR 的最大幅度 |
| `spike.count` | playlike 异常高于核心的对局数 |
| `spike.max` | 单局 playlike 高于核心的最大幅度 |
| `blocklist.hit` | 是否在黑名单（0/1） |

### 规则示例

**嫌疑：playlike 与 MMR 差距过大**

- 左值：`mmr_playlike.max`
- 运算：`-`
- 中值：`mmr.min`
- 比较：`>=`
- 右值：`800`
- 权重(真)：`80`

**嫌疑：社区对局过少的新号**

- 左值：`data.community_match_count`
- 比较：`<`
- 右值：`20`
- 权重(真)：`15`

## 四、UI 校准（拖动式固定流程）

### 打开方式

主界面 → **UI 校准** → **开始校准**

### 流程（共 11 步）

1. **拖动准星到 1 号槽**，松开 → 程序自动切到 SC2 并 **右键** 该位置  
2. **拖动准星到「移出房间」** 菜单行，松开 → 记录菜单偏移  
3. **依次拖动到 2~10 号槽** 确认各槽右键坐标  
4. **保存并应用**

踢人使用 **脚本方式**（右键槽位 + 按偏移左键菜单），不再使用 OCR。

### 房间状态

程序读取主机句柄（`SC2+3E2F340`）并在 roster 内存中定位玩家列表；校准基址不匹配当前账号时会自动改用 profile 扫描。

## 五、踢人相关配置（user.toml）

```toml
[scoring]
kick_threshold = 100.0    # 总分达到此值且开启自动踢时踢人

[actions]
dry_run = false           # false 才会真正点击
auto_kick_enabled = true  # 需构建版本允许
kick_fast_path = true     # 使用校准坐标快速踢人

[calibration.kick_menu_offset]
dx = 0.06                 # 菜单相对槽位右键点的 X 偏移（归一化）
dy = 0.07                 # 菜单相对槽位右键点的 Y 偏移

[calibration.kick_slot_step]
dx = 0.0
dy = 0.066588             # 相邻槽位 Y 间距

[[calibration.slot_regions]]
x = 0.124
y = 0.321556
# … 共 10 个槽位
```

## 六、录像自动上传

- 无需手动「扫描录像」；退房后程序自动在录像目录中查找 KS2 对局并上传。
- **数据源** 中可指定额外录像目录；留空则按本机 Battle.net 句柄自动搜索。
- 校准向导中的 **录像上传状态** 可查看待上传数量与搜索路径。

## 七、常见问题

**Q：规则改了但不生效？**  
A：需在规则编辑器点 **保存**；或确认 `config/user.toml` 已更新并重启程序。

**Q：一直显示在房间中？**  
A：确认 `data/probe_calibration.json` 的 `struct_base` 正确。程序仅在该地址读取 440 字节 roster；退房后该处应无有效玩家数据。可用 UI 校准 → **测试识别** 查看「440B roster 有效」是否为否。

**Q：踢人没反应？**  
A：检查是否勾选 Dry Run、是否为房主、是否已完成 UI 校准、槽位号是否与界面「槽位」列一致（1–10）。

**Q：找不到校准入口？**  
A：请更新到最新版；主界面右上角 **UI 校准** 按钮应始终可见。

**Q：所有玩家都显示「极高嫌疑」？**  
A：检查 `config/user.toml` 中 `[scoring]` 的 `tier_medium` / `tier_high` / `tier_critical` 是否为合理值（默认约 40 / 60 / 85）。若均为 `0`，则任意分数都会显示极高嫌疑。

**Q：玩家名册去哪了？**  
A：玩家名册（xlsx 同步）功能已移除；玩家信息由内存模式6 自动从 SC2 读取，昵称与 MMR 来自社区 API。
